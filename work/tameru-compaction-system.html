Tameru (ためる) Compaction System

Deterministic, query-aware context compaction for long-running AI agents. Local, fail-open, with recoverable originals.

Year
2026
Status
v1.9.0 source, Apache-2.0 repo
Role
Solo design & development
Link
GitHub

Overview

Named from ためる (tameru), Japanese for "to store up". Long-running agents fill their context with tool output, plans and history, and something has to decide what survives when the window runs out. Most systems answer that with a model-written summary. Tameru's default answers it with selection: it is deterministic and purely extractive, so the compacted context is made of real spans from the transcript rather than generated paraphrase, and every decision can be audited and reproduced. The engine is harness-agnostic: a Python function, a command-line tool and a transcript adapter, with harness plugins kept in separate repositories.

TL;DR

  • 82.4% mean characters saved, 25/25 required strings, zero leaks across 16 shared cases
  • 3.05 ms median wall time; no model call in the default path, standard-library core
  • 2,016 tests passed, 4 skipped; 15/15 release QA cases; a tracked 228-case red-team harness
  • Hermes plugin 1.9.1 in the official catalogue; DeepSeek Harness plugin in development

Why extractive

Abstractive summaries read smoothly but they lie quietly: details get paraphrased, numbers drift, and there is no way to trace a claim back to the original text. For an agent acting on its own history, that is a correctness problem, not a style problem. The default strategy keeps the ground truth intact: the compacted context is made of real spans, and if a span is dropped it was a deliberate, recorded decision. Optional summarise and auto strategies exist, but the shipped default makes no model call.

Measured results

On a shared 16-task corpus covering documents, configuration, Git/npm/YAML output, multilingual text, saturated grep, captured pytest and numbered-source cases: 82.4% mean characters saved, every required source string retained, zero planted forbidden strings leaked, at a 3.05 ms median. The same harness measures 53.4% for a TF-IDF paragraph baseline, which kept 22/25 required strings and leaked 5. Third-party methods (LCC, Headroom, Laya) were measured on an earlier release and are reported separately in the repository's comparison.

A separate 15-case release QA battery passes every case, including git history, multi-hop documents, Japanese, Chinese and Arabic text. The 4,000-record synthetic document completes in about 114 ms in the committed run, against a 1,200 ms gate. Budget ratios from 0.1 to 0.7 retain every required string with no leaks; mean character savings run from 77.8% at 0.1 to 24.8% at 0.7.

What is in 1.9.0

  • Structured reports stay whole: selected SARIF findings, notebook cells, Kubernetes identity and status, whole Git log entries and patches, LCOV records and JUnit testcases
  • Safer fail-open: JSON numbers that reserialisation would change, malformed XML or Unicode, and ambiguous structured input return the exact original
  • Faster credential screen: a 16x log from 5.8 s to 2.9 s with the same answers
  • A tracked 228-case red-team harness; four of the five safety leaks and all four gold losses from 1.6.0 are fixed, and the fifth was traced as not a leak
  • Coverage across 20 script and language families, including Japanese, Chinese and Arabic release cases
  • A golden-output test over 216 input and query combinations and 26 option sets

Compaction results are unchanged from 1.6.0 on the comparison corpus: the same 16 cases, the same required and forbidden strings, and the same savings.

Design principles

  • Deterministic default: the same input always produces the same compacted context
  • No model in the loop: the default strategy is a selection problem, not a generation task
  • Query-aware: what gets kept depends on what the agent is currently trying to do
  • Fail-open: weak queries, malformed input or insufficient savings return the original text
  • Recoverable: a cut can point to its original, optional and off when no persistence is wanted
  • No required dependencies: a single importable package, Python 3.10+

Integrations

The engine is the same everywhere. A harness plugin adds what is specific to that harness: when to act, how to show it, where to keep state. Each plugin lives in its own repository and vendors the engine unchanged.

Hermes hermes-tameru-plugin 1.9.1, released and listed in the official Hermes plugin catalogue. Its feature set includes adaptive policy and self-tuning, pinned instructions, Keep and Restore, the Artifact Trail, a Desktop panel and /tameru commands.
DeepSeek dsh-tameru 0.1.2, in development and unreleased. Adds a bar, a card, pins, Keep and Restore on the Harness's own extension points.

In practice

Tameru ships as a standalone Hermes plugin, merged into the official Hermes plugin catalogue in October 2026 and now at 1.9.1. Users install the catalogue entry and select context.engine: tameru; the plugin vendors the engine and adds the Hermes-specific layer: adaptive compaction, pinned instructions that survive every summary, Keep and Restore, an Artifact Trail and a Desktop panel. For other frameworks the engine exposes a Python API, a tameru-compress CLI and a generic transcript adapter, with an integration guide for host message lists and task-derived queries.

A DeepSeek Harness plugin, dsh-tameru, is in development at 0.1.2: the bar, card, pins, Keep and Restore are built and tested against the real Harness packages, but no real model has run through it yet. Its first whole-session replay is deliberately cautious: at the shipped settings it is cost-neutral against the Harness's stock pruner, mostly because it almost never acts, and with the confidence gate lowered sessions cost about 3% more while holding about 0.7 more of five needed facts.

Status

v1.9.0 is the verified source on GitHub. The repository is now Apache-2.0, while the pinned 1.9.0 commit itself remains MIT. It passed 2,016 tests and a 15/15 release QA battery, with benchmarks, fixtures, a red-team harness and a comparison harness in the repository. No 1.9.0 release tag, GitHub Release page or PyPI package is published yet, so install is pinned to the engine commit. The Hermes plugin is at 1.9.1, and the DeepSeek Harness plugin is unreleased.

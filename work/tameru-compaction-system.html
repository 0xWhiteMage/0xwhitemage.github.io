Tameru (財める) Compaction System

A query-aware, deterministic, purely extractive context compaction engine for autonomous LLM agents.

Year
2026
Status
v1.5.0, MIT
Role
Solo design & development
Link
GitHub

Overview

Named from 財める (tameru), Japanese for "to save or store up". Long-running agents fill their context with tool output, plans and history, and something has to decide what survives when the window runs out. Most systems answer that with a model-written summary. Tameru answers it with selection: it is deterministic and purely extractive, so the compacted context is made of real spans from the transcript rather than generated paraphrase, and every decision can be audited and reproduced.

TL;DR

  • 81.9% mean characters saved, 25/25 required strings, zero leaks
  • 12.83 ms median wall time; ~4.6x faster per tool result in v1.5.0
  • 15/15 release QA battery, 1,319 tests, stdlib-only core
  • Merged into the Hermes plugin catalogue: context: engine: tameru

Why extractive

Abstractive summaries read smoothly but they lie quietly: details get paraphrased, numbers drift, and there is no way to trace a claim back to the original text. For an agent acting on its own history, that is a correctness problem, not a style problem. Extractive compaction keeps the ground truth intact. If a span is dropped, it was a deliberate, logged decision.

Measured results

On a shared 16-task corpus covering documents, configuration, Git/npm/YAML output, multilingual text and saturated grep: 81.9% mean characters saved, every required source string retained, zero planted forbidden strings leaked, at a 12.83 ms median. The same harness measures 36.3% for LCC mechanical, 50.5% for Headroom's TextCrusher and 53.4% for a TF-IDF baseline on identical input.

A separate 15-case release QA battery passes every case, including git history, multi-hop documents, Japanese, Chinese and Arabic text, and a 4,000-record synthetic document completed in 100.4 ms. Budget ratios from 0.1 to 0.7 all retain required strings with no leaks.

What is in 1.5.0

  • Hardened for untrusted output: quadratic-time paths closed, lone surrogates handled, a 20,000-newline input from over 20 seconds to milliseconds
  • Wider secrets screen on the recovery cache: 70 of 80 credential shapes recognised, up from 29
  • Roughly 4.6x faster per tool result: a 650 KB log sequence from 4.05 s to 0.61 s, a 50 KB log from 443 ms to 66 ms
  • Plain-word diff and grep questions keep whole hunks, file headers and definitions

Compaction results are unchanged: the comparison corpus, QA battery and every budget ratio score exactly as before.

Design principles

  • Deterministic output: the same input always produces the same compacted context
  • No model in the loop: compaction is a selection problem, not a generation task
  • Query-aware: what gets kept depends on what the agent is currently trying to do
  • Fail-open: weak queries or insufficient savings return the original text
  • Zero dependencies: a single importable package, Python 3.10+, MIT licensed

In practice

Tameru ships as a standalone Hermes plugin, merged into the official Hermes plugin catalogue in October 2026. Users install the catalogue entry and select context: engine: tameru; the plugin vendors the engine and adds a bounded recovery path. For other frameworks it exposes a Python API, a tameru-compress CLI and a generic transcript adapter, with an integration guide for host message lists and task-derived queries.

Status

v1.5.0 is released under MIT on GitHub: 1,319 tests passed and a 15/15 release QA battery behind it, with benchmarks, fixtures and a comparison harness in the repo.
